## M4 step 4: bots play whole runs
- **Policies** (`runPolicy.ts`): what a bot does outside a fight. Random takes any reward and rest action; the others take a new structure before an upgrade (Count-Min Sketch, then LogLog), then Power, Resolve, Recovery, Capacity, Slots, and fuse whenever possible. `Bot.runPolicy` is optional (sensible by default).
- **Runner** (`runRunner.ts`): `playRun` wraps the existing fight-level bots (a new player per fight; Oracle still gets the true answers) and records the outcome, fights by tier, rewards, fusions, what was deployed, the opener and the strikes. `isWrongStrike` is now shared with the fight runner.
- **Report** (`runReport.ts`, `runFormat.ts`): win rate with a Wilson interval, fights won per run, where lost runs ended, win rate by tier, and for won runs the turns, Certainty left, structures deployed, openers and fusion share. `checkTargets` tests the spec's targets and says why when it cannot (no winning runs).
- **Command**: `pnpm sim runs --bot <name>` or `--bots a,b,c` (`--n`, `--seed-base`, `--json`); the old "not available" stub is gone. About 0.06 s per run.
- **Tests** (written first and failing): 13 runner and policy, 19 report and targets, 8 format, 4 `runs` CLI tests (the stub test was removed). Mutation checks: 26 breaks; after adding tests for the boundaries, stalled fights, act order, fusion share, the first (not last) opener, a new player per fight, counted wrong strikes and the reward order, all are caught. (A first run of the opener test could not tell first from last because later fights also deployed Bloom; the test bot now deploys only in the first fight.)
