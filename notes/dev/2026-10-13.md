## M3 step 1: content and config
Code is in `packages/content/`.

| File | Purpose |
| --- | --- |
| `balance.json`, `src/balance.ts` | Adds `EXPECTED_TURNS`, `TURN_LIMIT_PENALTY`, `STARTING_LOADOUT` and a `TIERS` table (Minion, Elite, Boss). The schema checks ranges and that each trait or weak point range has `min <= max`. |
| `traits.json`, `src/traits.ts` | The level tables for the five stream traits and the weak point hints. `weakPointWeights(traits)` gives each weak point a base weight plus the hints of the enemy's traits. |
| `structures.json`, `src/structures.ts` | Name, aliases, the challenges it answers, knob range, summary, help and flavor text for each of the six structures. `findStructure(name)` matches a kind, display name or alias, ignoring case and punctuation. |
| `src/enemies.ts` | `generateEnemy(seed, tier)`: picks which traits are above Low and how strong, then draws weak points weighted by the hints. |
| `src/fight.ts` | `buildFightConfig({ seed, tier, loadout? })`: the rules from `balance.json`, a generated enemy, and the loadout (default: the starting loadout). |

## Notes on running the tests
The statistical tests are CPU- and memory-heavy and have a 60-second limit each. On a loaded or memory-starved machine a test can exceed that and fail with a timeout while the code is fine; the k=14 Bloom test is the most exposed. Rerun when the machine is idle, or pass `--testTimeout=` to raise the limit.

## M3 step 2: command parser and narrator
New package `packages/ui-core` (shared by the CLI now and the web UI later), plus `packages/content/narration.json`.

**Narration content** (`narration.json`, `content/src/narration.ts`)
- Templates for every kind of event, the enemy's tier and trait descriptions, and the usage and summary of each command.
- Templates use `{name}` variables. `EVENT_TEMPLATES` lists the variables each template may use, and loading fails if a template names any other, so a typo like `{slott}` is caught at startup.

**Parser** (`ui-core/src/parser.ts`): `parseCommand(input, { observation, loadout? })`
- Returns an engine action (with an optional note such as which structure `strike high` used), an information request (`status`, `query`, `help [topic]`), `quit`, `empty`, or an error message. It never throws.
- Context-aware: it reads the observation to find the first free slot, check free Space, check the knob range, know whether a Presence or numeric challenge is open, and work out `flagged` and `confirmed` targets from the structures' answers.
- Slots and targets are numbered from 1 for the player and converted to the engine's 0-based numbers. Command aliases: `ready`, `go`, `done`; `quit`, `exit`, `q`; `?` for help.
- Mistakes get an explanation, and a likely typo gets a suggestion (`blom` suggests `bloom`, `stike` suggests `strike`).

**Narrator and screens** (`narrator.ts`, `views.ts`)
- `narrateEvent` and `narrateEvents` turn events into lines. The first challenge also reveals the weak point; Presence challenges list their targets from 1.
- `describeEnemy` introduces the tier and lists each trait above Low.
- `renderStatus`, `renderQuery` (each structure's estimate, range and confidence, which Presence targets each flagged, and which are confirmed) and `renderHelp` (commands, structures, knobs).

**Tests (64 in ui-core: 39 for the parser, 25 for the narrator and screens; 5 for the narration content)**
- Every command, alias, error and edge case of the parser, using hand-built observations so the numbers are exact.
- Narration of every event kind, the enemy description, and the three screens.
- Three whole fights (a Presence, a Frequency and a Count enemy) played from typed commands through the parser, the engine and the narrator, checking no template variable is left unresolved.
- Mutation checks: an off-by-one in `remove`, a 0-based slot in the narration, counting one structure as "confirmed", and silently ignoring a missing template variable each fail tests. Two of these first slipped through, which exposed a gap (the test did not check that a singly flagged target was not marked confirmed); the test was strengthened.
