## M2 step 3: challenges and damage
Code is in `packages/engine/src/combat/`.

| File | Purpose |
| --- | --- |
| `damage.ts` | The three strike formulas: `frequencyStrike`, `countStrike`, `presenceStrike`. Pure arithmetic on a `DamageRules` object (the constants from `balance.json`). |
| `challenges.ts` | `issueChallenge` creates the question for a turn. `trueAnswer` and `gradeStrike` judge a strike against the live stream. |

Also added `outsideValue` in `enemies/stream.ts`: a value the enemy can never emit (the affine image of an index beyond the universe), used for never-inserted Presence decoys.

**Challenges**
- Frequency: names the heaviest live value (ties to the lowest). Returns null when nothing is live.
- Count: carries no data; the answer is the live distinct count.
- Presence: `T` distinct targets, shuffled. `T/2 − 1` to `T/2 + 1` are real, sampled from live values. Decoys are ghosts or outside values, equally likely while ghosts last. With fewer live values than wanted, the remainder are decoys.

**Grading**
- The challenge is not stored with its answer. The answer is recomputed from the `LiveSet` at strike time, which is valid because no events arrive between a challenge and its strike. A Presence target is real exactly when it is live.
- A strike of the wrong kind for the challenge throws a `RangeError`.

**Damage**
- Frequency: a force below the true count is blocked (costs `BLOCK_PENALTY`). Otherwise `BASE × (f/s)^OVERSHOOT_EXP`.
- Count: `BASE × (1 − |E − D| / (COUNT_TOL × D))`. An estimate on the edge of the band deals 0 and costs nothing. Beyond it costs `MISS_PENALTY`. With nothing live, only an estimate of 0 hits.
- Presence: `HIT_DAMAGE` per real target, `DECOY_PENALTY` per decoy. Targets are chosen by position, from 0, with no repeats.
- Damage is rounded to six decimals. Whole-number exponents use repeated multiplication, which gives the same result on every JavaScript engine.
- These interpretations are recorded in `SPEC.md`.

**Tests (35 new, plus 2 for outside values)**
- Damage: block boundary, full damage at the exact count, falloff, monotonic decrease past the count, non-integer exponent, rounding, symmetric Count tolerance, edge and miss behavior, nothing-live case, Presence hits and decoys, input validation.
- Challenges: Frequency naming and tie rule, Presence composition (distinct, real count 5 to 7 of 12, real values live, decoys not live), ghosts and outside values both appear, position does not reveal real targets, determinism, sparse and empty streams, true answers, grading, and wrong-kind rejection.
- Mutation checks: an off-by-one in the block test fails 3 tests; removing ghost decoys fails 1; dropping the absolute value in the Count formula fails 3.
