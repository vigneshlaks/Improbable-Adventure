# 2026-10-18

## M7 exporter, stage 1: sizing
- New package `packages/exporter` (depends on content and engine). `sizing.ts` has `sizeBloom`, `sizeCountMin`, `sizeHyperLogLog`, `sizeLogLog`, `sizeLinearCounting`, `sizeReservoir`, `sizeExact` and `sizingConstants` (structure constants plus counter and register bits and `defaultError`). `EXPORT_DEFAULT_ERROR` 0.01 added to `balance.json` and its schema. Formulas and modes are in SPEC.md (Exporter, "Sizing").
- Bug found by the first test run: sizing a Bloom Filter by the formula alone gave k = 7 (from 6.64) and a real rate of 1.003 percent for a 1 percent target; the size now grows until the real rate meets the target.
- Mutation checks (Count-Min depth rounding, Linear Counting error formula, the sample-size constant) are all caught. Scaling the Bloom formula size by 0.9 is not caught because the grow loop corrects it (an equivalent change). One mutation (dropping the `- 1` in the Linear Counting error) made the doubling search loop forever; it now refuses past 2^50 bits.
- Browser check of M6 done earlier today: heatmap, register bars, Stable Bloom and Exact Memory strips look right; a short strip did not fill its width (fixed, commit `2a3ceb1`); a scripted losing run offers the replay download.
- Python on this machine is 3.9.6 with pytest 8.4.2; CI will need a Python step for the generated toolkit tests.
