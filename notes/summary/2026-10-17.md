# Summary: 2026-10-17

## Changes
- **The act is now winnable by a sensible bot.** Starting Certainty is 150 (was 100) and enemy HP is Minion 20, Elite 30, Boss 50 (was 40, 90, 200). Over 300 whole runs the greedy bot now wins 47.7% (was 1.3%), the prober 29.7%, the cautious bot 12.0%, the random bot 0.3% and the Oracle all of them.
- **Four of the six balance targets are met** (Random under 5%, Oracle over 95%, no dominant opener, every MVP structure used). **Two are missed and written down:** the greedy bot wins 47.7% against a target of 55 to 70%, and 37.6% of its strikes are wrong against a target of 10 to 30%.
- **Why it stops there.** More Certainty, a bigger rest heal, extra turns, bosses that hit less and a gentler penalty for overshooting a Frequency strike all moved the greedy bot by only about 2 points. The fights it still loses are Frequency fights, lost to the turn limit, because it cannot find the shielded value's count: that is a question about the bot and the structures, not the tier numbers.
- **The report got better.** It now says how many fights in each tier were lost to the turn limit instead of to Certainty (that is what exposed the cause), and the opener and structure targets are checked over the whole Greedy family together, which is what the spec means (the prober opens with Reservoir Sampling by definition).
- 546 tests pass; the tests were written first and checked by breaking the code on purpose.

- **Why Frequency fights are lost (recorded, not fixed).** The Count-Min Sketch is given only 32 columns at the starting Space, so its estimate is many times the true count and the strikes do almost no damage. This is deferred to the Phase 2 structures.

- **The terminal now plays a whole run.** `pnpm cli --run` starts an act: seven fights, a reward screen after each (`choose 2` takes the second), a rest stop before the Elite where you can fuse structures (`fuse hll`) or `leave`, and a win or loss at the end. It was played by hand on the real content. The parts that read commands and show the reward and rest screens live in the shared UI package so the web version can reuse them. 589 tests pass.

- **Enchantments exist (first slice).** Enchantments are rewards that go into a pack; at a rest stop `enchant seeded bloom` attaches one to a structure you own (one per structure, and it can be moved or swapped), and the structure carries it into every later fight and shows it in its name. The first one built is Seeded (a secret hash seed per fight); it is not offered as a reward yet because it only matters against the collision-hunting enemy of a later milestone. Merge waits for multi-enemy fights. 623 tests pass.

- **Steady is built.** Taking the Steady enchantment and attaching it to Count-Min turns it into a Count-Min that counts conservatively (on a skewed stream with 32 columns its overshoot fell from 34.8 to 0.3), at the price of not being able to take deletes back; attached to LogLog it becomes SuperLogLog (error about 1.05 over the square root of its registers instead of 1.30). Both cost 10% more Space. Steady is now offered as a reward and the bots use it. It lifts the greedy bot's Minion Frequency fights from 91% to 99% but does not change Elite or Boss ones, so the Frequency gap is only partly closed. 185 tests pass (see the next entry).

- **Fewer tests, same checks.** Back-to-back tests on the same topic are now merged into one, which took the count from 645 to 185 without removing a single assertion (checked by counting them) or weakening anything (breaking the code on purpose is still caught everywhere I tried). New tests will be written one per topic.

- **Fading is built (the Stable Bloom Filter).** A Bloom Filter with Fading holds small counters that count down as new values arrive, so it never fills up and deleted values fade, but it forgets old values. It works as designed and is tested against the published behaviour. Honest result: it is a trap at these Space sizes. The greedy bot's Elite Presence fights go from 100% with a plain Bloom Filter to between 0% and 14% with Fading, even against heavy deletions and growth, because the questions are about all live values, old ones included. It is offered as a reward because the spec lists it, but the bots never take it. A bug in my own forgetting formula was caught by its test along the way. 190 tests pass.

- **Fading tuned.** Its memory window was far too short; now it remembers about 1.5 times as many values as it has cells. On Elite and Boss sized streams it beats a plain Bloom Filter by roughly 10 to 25% in score (and loses on small Minion streams), so it is a real, if modest, trade-off.
- **Light is built** (the last enchantment): Count-Min counters shrink to 8 bits and HyperLogLog registers to 3, so the same Space buys four times the columns or about 1.7 times the registers, until a cell fills (a counter stops at 255, a register at rank 7) and the answer loses its upper bound. It makes the greedy bot's Minion Frequency fights 100% but Boss ones 7%, so the bots do not use it. I left LogLog out of Light (it needs many values per register and 3 bits cannot hold them) and replaced the spec's "-25%" with whole-bit widths. 195 tests pass.

- **Replays (Milestone 5) are built.** A finished run can be saved as a small file (5 to 8 KB: the seed, the rules it ran under, every action, and the result it claims) and checked later by playing it again. Any tampering is rejected with a reason: an action the game refuses, a run cut short, a changed seed or enemy, a claim of a faster time or more Certainty left, or an older rules version. Wins can be ranked by fewest turns, then most Certainty left. `pnpm sim replay record|verify|rank` does this for the bots, `pnpm cli --run --record file.json` for a human, and a folder of five recorded runs is re-checked by the tests so a rules change cannot slip by unnoticed. 203 tests pass.
