# Summary: 2026-10-09

## Repository
- pnpm workspace with `packages/engine` (pure game logic) and `packages/content` (tuning constants).
- Strict TypeScript, Vitest, ESLint, and a GitHub Actions workflow. `CLAUDE.md` holds the project rules and `SPEC.md` the build spec.
- Lint enforces engine purity: no `Math.random`, no `Date.now`, no imports from other packages or `node:*`.

## Engine
- **MurmurHash3 (32-bit)**, written in the repo and checked against 13 published vectors.
- **Double hashing** derives k positions from two hashes: `h1 + i·h2 (mod m)`.
- **Seeded random numbers** (sfc32). Named sub-streams derive from the seed and name alone, so drawing from one never shifts another. State round-trips through JSON.
- **Stats helpers:** normal quantile (`zForConfidence`), binomial upper bound, `clamp`.

## Structures
Each takes a Space budget in bits, derives its own parameters, and answers with an estimate plus low and high bounds.

| Structure | Answers | Behavior |
| --- | --- | --- |
| Exact Memory | All | Exact until full (64 bits per distinct value), then refuses new values and widens its bounds by the number refused. Handles deletes. |
| Reservoir Sampling | All, roughly | Uniform sample, estimates scaled by sample fraction, normal-approximation bounds. Cannot see deletes, so deleted values stay as ghosts. |
| Bloom Filter | Presence | No false negatives. False-positive rate follows `(1 − e^(−kn/m))^k`. Ignores deletes. |
| Count-Min Sketch | Frequency | Never underestimates a live value. Reports confidence `1 − e^(−depth)`. Supports deletes. |
| LogLog | Count | Error about 1.30/√m, biased on small streams. Ignores deletes. |
| Linear Counting | Count | Estimate `−m·ln(V)`. When no zero bits remain, the upper bound is infinite. Ignores deletes. |

Bloom, Count-Min and LogLog also merge with a same-shaped, same-seeded instance.

## Tests
- Every structure has unit tests and a 1,000-trial seeded statistical test against its theoretical error.
- 102 tests pass; lint is clean.

## Content package
- `balance.json` holds the spec's tuning constants at placeholder values, validated by a Zod schema that rejects missing, extra or out-of-range keys.
- The engine receives only the two constants it needs (bits per stored value, default confidence) as a constructor argument.

## Known limitations
- LogLog reports 95% bounds even on streams too small for its error law to hold.
- Linear Counting's infinite upper bound has no JSON encoding yet.
- Structures hold typed arrays and Maps, so they have no JSON snapshot form yet.
- The Frequency challenge assumes the enemy supplies the value to query; the spec does not say.

- Constants: `packages/content`
- Tests: `pnpm test` (pnpm 10, Node 22 or newer)
